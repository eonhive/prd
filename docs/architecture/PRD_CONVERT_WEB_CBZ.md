# Convert Web — bounded CBZ comics

_October 29, 2026. Repository implementation; live UI acceptance, release and deployment pending. Decision: PRD-053._

The existing `convertInBrowser` entry and `/convert/` workspace now accept small `.cbz` image archives. They reuse the [existing CBZ adapter](PRD_CONVERT_CBZ.md), validator archive reader, canonical Comic model, shared conversion assembly, packager and Viewer. There is no new archive decoder, format schema, renderer, runtime dependency or service.

## Adapter and resource boundary

Generic dispatch lazily loads CBZ only for a CBZ filename; the adapter also requires an ordinary ZIP signature. The original `convertMarkdownInBrowser` remains Markdown-only. HTML and Markdown behavior stay compatible. A portable internal image-sequence helper supplies the existing English numeric comparison and title formatting; the public Node image-sequence export retains its host-path wrapper.

The browser collector accepts bounded archive image bytes through the existing `collectImage` contract. Archive member paths stay literal, including percent characters; they are not interpreted as URL-encoded selected-resource references. Extension/signature screening, stable resource IDs and reference mappings match Node. Separate selected images are rejected for CBZ, including before file reads in the web job. The interface clears earlier supporting-image selections when choosing CBZ and explains that pages come from the archive.

The shared reader validates paths, duplicates, ZIP records and CRC before interpretation. Limits cover ignored metadata and hidden members as well as accepted pages. Renamed Office/EPUB/PRD markers, unreadable archives, malformed members and archives without supported pages fail explicitly. No member is extracted to disk or retrieved over the network. Metadata XML, scripts and embedded objects are not executed or parsed as document behavior.

## Budgets and lifecycle

Browser limits remain 4 MiB compressed input, 8 MiB per expanded member, 24 MiB combined expanded bytes, 128 archive entries including directories/ignored members, and 20,000 candidate pages/resource attempts. The browser API can only tighten limits. These intentionally exclude many ordinary full-size comic archives; the Node library has configurable limits. The app retains its 20-second total job deadline, buffer transfer, cancellation, worker termination and late-result rejection.

The app skips UTF-8 decoding for CBZ. It never prints binary source into the text preview. Source review states whether the exact original archive is attached and directs the reader to real resource mappings and the existing Viewer. Exact source retention defaults on, including original metadata/hidden members; opt-out warns. Retention is not redaction. Raster byte signatures are not full image decoding or pixel/memory limits; worker deadlines are not an OS/native/GPU sandbox.

## Profile and page sequence

Automatic classification selects `comic`; explicit Comic is compatible. General Document and Storyboard are rejected by the existing assembly profile check. The web UI offers compatible profile choices for the selected source family and resets profile/page options when the source changes.

The current canonical Comic root has ordered `panels` and no reading-direction field. The UI therefore offers **Natural filename order** or **Reverse filename order**, not manga-direction controls. Additive shared Node/browser setting `comicPageOrder: "natural" | "reverse"` applies only to comic input. Default/explicit natural preserves existing output. Reverse reorders a cloned panel array, retaining every page's original ID, asset reference and description; resource mappings remain in collection order. The existing report v1 adds a `comic-page-order-reversed` adaptation warning. CLI commands/flags and default outputs are unchanged.

This is a sequence choice, not panel detection, cover selection, spread layout, right-to-left interpretation or OCR. Every CBZ conversion retains the existing inferred-order and filename-alt-text warnings. Fidelity fields stay conservatively partial/not-preserved; copied page image bytes themselves remain unchanged.

## Review and evidence

The result identifies **Comic**, labels the actual node count as **Pages**, exposes factual quality/resource maps and enables package/report downloads only after successful validation. **Preview in Viewer** hands off the exact generated archive to the existing comic renderer. Markdown/HTML source review remains escaped plain text.

The [actual example](../../examples/conversion-web/cbz/README.md) has three whole-page panels, three unchanged images and three warnings. It was generated by executing the browser export under Node, not downloaded from a browser. Both transports match Node logical files/report and open through the existing Viewer as fully supported Comic content. Reverse-order tests verify stable asset identity and Node parity.

Tests cover binary job handling, pre-read rejection, source snapshots, Buffer-free conversion, no source fetch, literal member names, ordering/omissions, unsafe ignored paths, corrupt CRC, per-member/aggregate/count/page budgets, high-ratio metadata, malformed/disguised sources, incompatible profiles/options and source retention. Installed-consumer smoke covers CBZ without Buffer and without the optional HTML parser. Existing Node/CLI import and browser Markdown/HTML tests remain regression protection.

Fresh live review remains pending while browser automation is disabled: real picker/drop/cancel/recovery, page-order control changes, module chunk loading under `/` and `/prd/`, both themes/mobile/keyboard, downloads and exact-archive Viewer image rendering/navigation. Automated component/build/Viewer-opening evidence does not close those checks. No historical screenshot is used as new evidence and no deployment is included.
