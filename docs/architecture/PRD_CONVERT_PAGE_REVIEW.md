# Convert Web — comic page-order repair

_October 29, 2026. Repository implementation; live UI acceptance, release and deployment pending. Decision: PRD-054._

This is the first focused conversion repair action: review imported CBZ filenames, move pages earlier/later, reset a draft, then apply an explicit sequence. It builds on [browser CBZ](PRD_CONVERT_WEB_CBZ.md) and keeps every imported page. It adds no image editor, PRD package editor, renderer, format extension or service. Full authoring remains Studio's responsibility.

## Source-backed application

Successful CBZ web jobs retain the explicitly selected immutable `File` and a settings snapshot in the existing in-memory `WebConversion` result. This context survives the existing Viewer handoff/return and successful repairs. Reload, clearing the result or choosing another source ends that review session; there is no persistent history, filesystem enumeration or source upload. The native file-input state itself is not restored.

Package source retention and session context are separate. Even with original-source packaging disabled, the selected CBZ remains available locally for review reruns. The interface states this; opt-out is not redaction or memory erasure. The context is never serialized into manifest, content or quality JSON. Results without this context display the order but require reconversion before applying changes.

`startComicPageReviewJob` reuses `startConversionJob` with that selected File, current title/identity and actual source-retention setting. It clears the filename-order setting, supplies explicit source page IDs, and reruns the existing adapter, resource collection, canonical assembly, validator and packager in the same worker. Existing source/archive/resource budgets, transfer policy, 20-second deadline, cancellation and cleanup apply. No second archive mutation/output pipeline exists.

## Shared conversion option

Additive Node/browser option `comicPageIds: readonly string[]` is mutually exclusive with `comicPageOrder`. It must identify every successfully imported page exactly once. Duplicate, omitted or foreign IDs fail; non-comic input fails. Empty/malformed input, more IDs than `maxNodes`, and IDs longer than 255 UTF-16 code units fail before asynchronous conversion. The array is copied before async extraction and again screened during assembly. These are tooling limits, not new PRD format maxima.

Assembly reorders a cloned canonical panel array. IDs, asset references, descriptions and collected resource mappings stay attached to their original source pages; image bytes are unchanged. The manifest/profile/content versions and default output remain unchanged. CLI flags and JSON contracts are unchanged; the developer API and web workspace expose the option.

The existing report v1 includes `comic-page-order-reviewed` when explicit order is supplied. Source-extraction warnings remain. Each apply regenerates the report for the current configuration, rather than accumulating an interaction history or marking source problems resolved. Initial reversal is superseded by the explicit sequence; the mutually exclusive settings prevent ambiguity. Quality/fidelity claims remain conservative.

## UI and result lifecycle

The result contains an ordered filename/description list with native earlier/later buttons and explicit Apply/Reset actions. Buttons are bounded by list ends and disabled while processing. Move/reset/application focus targets the relevant list row; live status describes draft/application state. No additional page bitmaps are decoded for this list; the existing Viewer supplies artwork inspection.

Moves affect only the draft. Apply keeps the current result available until successful conversion replaces it. Failure or cancellation retains the previous archive/report and draft for retry. Downloads/Viewer continue to refer to the current package, not an unapplied draft. Download URLs are exposed only when their stored byte/type references match the current result, so a replaced result cannot briefly link to the preceding archive/report while effects update. Existing object-URL disposal remains.

This original order-only increment cannot add/remove pages, edit captions, select a cover, alter panel geometry or encode manga direction. Description repair now follows under the separately scoped PRD-055 continuation below. It does not interpret ComicInfo or certify source-order/description quality. Broader conversion repair and simultaneous source/result preview require separate scope.

## Evidence and remaining acceptance

The [actual reviewed example](../../examples/conversion-web/cbz-review/README.md) places source page IDs 2, 3, 1 in that order, with three unchanged images and four warnings. It was generated by executing the browser export under Node, not by clicking the web UI. Node/browser logical files/report match in both transports and the existing Viewer opens the result as fully supported Comic content.

Tests exercise complete permutations, invalid/oversized/conflicting options, pre-await Node/browser/job snapshots, exact assets/source identity, source opt-out, repeated review, rejected review, cancellation and existing Viewer ordering. Component checks cover native controls, unavailable-context recovery and the corrected browser-support copy. Native byte comparisons keep large-fixture parity assertions exact without recursively traversing millions of byte elements. Installed-consumer smoke exercises explicit order with Buffer unavailable.

Fresh browser inventory still reports **Local browser use is disabled in Work settings**. Real move/reset/apply/focus, failed/cancelled retry, both themes/mobile/keyboard, Viewer-return session context and latest-archive/report downloads remain pending alongside earlier conversion acceptance. Automated source/build/component/Viewer checks do not close these interactions; no old screenshot, alternate controller or permission change is used as substitute evidence.

## Description and draft continuation — PRD-055

The current **Review comic pages** / **Apply review** controls extend this action with [supplied descriptions](PRD_CONVERT_COMIC_DESCRIPTIONS.md) in canonical `alt`. Draft order/text now lives in the existing in-memory result context across Viewer return; it is not exported before successful apply. Failed/cancelled apply keeps the current output/draft and repeated order-only review retains applied text. Reset restores current package values. Reload or changing source/conversion settings ends the review. The original order-only example remains valid; the new described example is separate. Full live acceptance remains pending after browser availability briefly returned for native source selection and then stopped before conversion.
