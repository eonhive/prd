# Supplied comic descriptions example

`review.json` contains converter application settings: explicit source page IDs 2, 3, 1 and three supplied plain-text descriptions. It is not a PRD format extension. The descriptions were written after inspecting the repository's three demo PNGs; references to live updates, collaboration and offline sync describe labels in those illustrations, not a claim that this converter implements those services.

`converted.prd` and `quality.json` are actual `convertInBrowser` output from the existing [sample CBZ](../../conversion-cbz/sample-comic.cbz) plus these settings. They were generated by running the browser export under Node, not downloaded from a browser. The output has three unchanged images, canonical `alt` text keyed by source page identity and five warnings. The generated-description diagnostic reports three supplied descriptions and zero remaining filename-derived ones, with accuracy/completeness unassessed.

Both transports match Node logical files/report and open through the existing Comic Viewer. Source bytes and asset identities are unchanged. No AI, OCR, renderer or new schema is required.

For manual review, run `pnpm dev:web` and open `/convert/` at its printed URL. Convert the sample CBZ, edit fields under **Review comic pages**, move pages if needed, then choose **Apply review**. Use **Reset changes** to discard a draft. Viewer opens the current package while the unapplied draft remains available on return. Reload or changing source/conversion settings ends the local session. Source packaging opt-out does not clear session data.

Use plain text up to 2,048 characters per supplied description; blank/invalid changes cannot be applied. Content accuracy remains a human review responsibility. See [the policy and exact acceptance limits](../../../docs/architecture/PRD_CONVERT_COMIC_DESCRIPTIONS.md). Native CBZ selection was observed; live conversion/edit/apply/download acceptance stopped when browser use became disabled again.
